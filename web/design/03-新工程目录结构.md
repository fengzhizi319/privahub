# SecretPad 前端工程目录结构规范（最终版）

> 版本：3.0（最终标准版）| 规范架构：Feature-Sliced Design (FSD) + Clean Architecture + Monorepo
> 本规范定义了 SecretPad 现代化前端工程全量目录、包粒度与层级依赖规则。

## 6. 依赖规则

### 6.1 允许导入方向

```
app → pages → widgets → features → entities → shared
```

```
✅ features/auth → shared/*（任意）
✅ features/project → entities/project, entities/node, shared/*
❌ features/project → features/node（禁止跨 feature 引用）
✅ entities/node → shared/*
❌ shared/* → features/*（不能引用上层）
❌ entities/* → features/*（不能引用上层）
```

### 6.2 模块 Public API

每个 feature/widgets/pages 目录下必须包含 `index.ts`，仅导出稳定接口：

```ts
// features/project/index.ts
export { ProjectCard } from './ui/project-card';
export { ProjectTable } from './ui/project-table';
export { projectQueries, projectMutations } from './api';
export type { Project, ProjectStatus } from './model/types';
```

## 7. 目录职责与隔离定位

| 新工程目录 | 职责与隔离定位 |
|--------|----------------|
| `apps/secretpad/src/pages/` | 路由薄壳，仅负责组合 widgets 与 features |
| `apps/secretpad/src/features/` | 核心业务领域，按 FSD 隔离，切分为 `api/lib/model/ui` |
| `widgets/` + `shared/ui/` | 复用 UI 块归 widgets，基础原子组件收敛至 design-system |
| `packages/api-client/` | OpenAPI 契约生成 + Zod 运行时响应校验 |
| `features/*/model/` | Zustand 切片，可销毁、可测试、具备单例隔离能力 |
| `features/auth/ui/` | 统一 `RequiredAuth` 与 `RequiredPermission` 两个权限守卫 |
| `packages/dag-next/` | 独立的拖拽画布引擎包，原生 ESM 化，与主应用高内聚低耦合 |
| `packages/utils/` | 跨项目共享纯工具库 |

## 8. 配套脚本

```bash
# 创建新 feature（自动生成 api/lib/model/ui/index.ts 模板）
pnpm create:feature project

# 生成 API 客户端（从后端 Swagger）
pnpm codegen:openapi --url https://backend/swagger.json

# 开发
pnpm dev                          # 启动 Vite dev server

# 校验
pnpm lint                         # ESLint + Biome
pnpm typecheck                    # tsc --noEmit
pnpm test                         # Vitest
pnpm test:e2e                     # Playwright

# 构建
pnpm build                        # 生产构建
pnpm analyze                      # 产物分析（visualizer）

# 发布
pnpm changeset                    # 变更日志
pnpm release                      # 版本发布
```
