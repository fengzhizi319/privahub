# SecretPad 前端架构设计方案（最终版）

> 版本：3.0（最终标准版）| 适用范围：SecretPad 隐私计算管理平台前端
> 目标：构建基于「Vite 5 + FSD 6层架构 + TanStack 生态 + Zustand + 设计系统」的模块化工业级前端。

---

## 1. 核心设计目标与验收标准

| 维度 | 架构设计目标 | 验收标准 |
|------|--------------|----------|
| **解耦框架** | 业务逻辑彻底与具体框架解耦 | 业务代码零框架特定 API 依赖，路由、构建、请求层均可灵活插拔 |
| **模块自治** | 业务领域完全独立自治 | 任何 Feature 具备独立 `api/model/lib/ui`，可通过 Module Federation / 微前端独立发布 |
| **类型安全** | 端到端类型推导与运行时防线 | OpenAPI 自动生成 TypeScript 类型 + Zod 运行时 Schema 校验，阻断接口变异 |
| **状态可控** | 分层管理服务端与客户端状态 | 服务端状态由 TanStack Query 统一缓存，客户端 UI 状态使用 Zustand 快照管理 |
| **极致体验** | 路由级异步加载与乐观更新 | 路由级代码分割、骨架屏、乐观更新，冷启动 < 1s，TTI < 3s |
| **工程领先** | 现代化质量门禁与高构建效率 | Vite HMR < 200ms、ESLint Flat Config + Biome 格式化、CI 全链路校验 |
| **安全合规** | 严格的安全防线与 RBAC 模型 | Token httpOnly Cookie 存储、防 XSS DOM 净纯化、统一 RBAC 平台权限守卫 |
| **可观测性** | 全链路错误与性能追踪 | 整合 Sentry + Web Vitals + 业务埋点，生产环境异常 5 分钟内精确定位 |

## 2. 架构分层设计（FSD + Clean Architecture 融合）

```
┌──────────────────────────────────────────────────────────┐
│                   apps/secretpad                         │
│              (Vite entry, React 18)                        │
├──────────────────────────────────────────────────────────┤
│  pages/          路由薄壳：组合 widgets + features         │
├──────────────────────────────────────────────────────────┤
│  widgets/        可跨页面复用的复合 UI 块                   │
│                  (header, sidebar, filter-bar, table)      │
├──────────────────────────────────────────────────────────┤
│  features/       业务领域模块（自治）                       │
│  ├─ api/         queries + mutations (TanStack Query)      │
│  ├─ model/       zustand slice / types                     │
│  ├─ lib/         domain logic（纯函数）                    │
│  ├─ ui/          components + hooks                        │
│  └─ index.ts     public API（唯一出口）                    │
├──────────────────────────────────────────────────────────┤
│  entities/       跨领域实体类型与简单规则                   │
│                  (User, Node, Project, DataTable)          │
├──────────────────────────────────────────────────────────┤
│  shared/         共享基础设施                              │
│  ├─ api/         client + interceptors + generated         │
│  ├─ ui/          design system 原子组件                    │
│  ├─ hooks/       通用 hooks                               │
│  ├─ lib/         utils, sanitize, logger, result           │
│  ├─ theme/       tokens + theme-provider                   │
│  ├─ i18n/        国际化配置                               │
│  └─ config/      环境变量、平台常量                        │
└──────────────────────────────────────────────────────────┘
```

### 单向依赖约束规则：
```
app → pages → widgets → features → entities → shared
```
1. **同层隔离**：同层模块不可互相直接引用。
2. **禁止反向依赖**：下层绝对禁止引用上层逻辑。
3. **Feature 间通信**：Feature 之间严禁直接 `import`，必须通过 URL SearchParams 或 Shared 事件总线通信。
4. **Public API 屏障**：所有模块必须通过 `index.ts` 暴露对外接口，禁止深层目录私有引用。

## 3. 技术选型规范

| 维度 | 选用方案 | 选型依据与职责 |
|------|----------|----------------|
| 构建引擎 | **Vite 5 + React 18** | 原生 ESM 极速冷启动，秒级 HMR，产物透明可控 |
| 路由系统 | **TanStack Router** | 端到端类型安全，支持路由 Loader 数据预加载与 SearchParams 类型序列化 |
| 服务端状态 | **TanStack Query v5** | API 自动化缓存、去重、失效控制、指数退避重试与乐观更新 |
| 客户端状态 | **Zustand + Immer** | 轻量可销毁 Store，支持局部隔离、单测及微前端隔离 |
| 表单引擎 | **React Hook Form + Zod** | 高性能无重绘表单、类型安全声明式校验 |
| 网络请求 | **openapi-fetch + Axios** | 零运行时类型推导 + 拦截器统一集中管理 |
| 运行时校验 | **Zod** | Response Schema 运行时强校验（开发抛错，生产上报） |
| 样式系统 | **Tailwind CSS + CSS Variables** | Design Tokens 变量化管理、主题动态无感切换 |
| UI 组件库 | **Ant Design 5 + 自研 Design System** | 保留已有设计资产，通过 ConfigProvider 消费 Token |
| 画布引擎 | **独立包 `packages/dag-next` (AntV X6)** | DAG 画布逻辑物理隔离，与主应用解除耦合 |
| 测试体系 | **Vitest + RTL + MSW + Playwright** | 与 Vite 同构，覆盖单元测试、API 集成测试与 E2E 关键流程 |
| 代码规范 | **ESLint 9 Flat + Biome** | Biome 极速格式化，ESLint 规范集中管辖 |

## 4. 核心领域与底层设计

### 4.1 认证与授权规范（Auth）

```
features/auth/
  ├─ api/        auth-queries.ts, auth-mutations.ts
  ├─ lib/        rbac.ts（权限判定纯函数）, platform-type.ts（CENTER/EDGE/P2P 模式）
  ├─ model/      auth-store.ts（Zustand 管理用户内存状态）
  └─ ui/         LoginPage, RequiredAuth, RequiredPermission, usePermission()
```
- **鉴权收敛**：通过 `RequiredAuth` 与 `RequiredPermission` 组合守卫接管全局路由与按钮级别权限。
- **安全存储**：Token 由后端写 httpOnly Cookie 管理，前端内存存储 Auth 状态，彻底避免 XSS 窃取风险。

### 4.2 服务端状态（TanStack Query）

```typescript
// features/project/api/project-queries.ts
import { queryOptions } from '@tanstack/react-query';
import { apiClient } from '@secretpad/api-client';

export const projectQueries = {
  all: () => ['projects'] as const,
  list: (params: ListProjectParams) =>
    queryOptions({
      queryKey: [...projectQueries.all(), 'list', params],
      queryFn: () => apiClient.GET('/api/v1alpha1/project/list', { params }),
    }),
  detail: (id: string) =>
    queryOptions({
      queryKey: [...projectQueries.all(), 'detail', id],
      queryFn: () => apiClient.GET('/api/v1alpha1/project/get', {
        params: { query: { projectId: id } },
      }),
    }),
};
```

### 4.3 客户端 UI 状态（Zustand）

```typescript
// features/dag/model/dag-ui-store.ts
import { create } from 'zustand';
import { devtools } from 'zustand/middleware';

interface DagUIState {
  selectedNodeId: string | null;
  zoom: number;
  setSelectedNodeId: (id: string | null) => void;
  setZoom: (zoom: number) => void;
}

export const useDagUIStore = create<DagUIState>()(
  devtools((set) => ({
    selectedNodeId: null,
    zoom: 1,
    setSelectedNodeId: (id) => set({ selectedNodeId: id }),
    setZoom: (zoom) => set({ zoom }),
  }))
);
```

### 4.4 设计系统与主题机制（Design System）

```
packages/design-system/
  ├─ tokens/            CSS Variables / Design Tokens (JSON)
  ├─ theme/             亮色/暗色/高密度主题
  ├─ components/        基础控件 (Button, Table, Form, Modal)
  └─ stories/           Storybook 组件交互文档
```
- 主题切换通过 HTML `data-theme` 属性结合 CSS Variables 实现，做到零闪屏。
- Ant Design 5 统一接入 ConfigProvider 消费 Design Tokens。

### 4.5 类型安全路由（TanStack Router）

```typescript
// apps/secretpad/src/app/routes.tsx

const rootRoute = createRootRoute({ component: AppLayout });

export const pipelineRoute = createRoute({
  getParentRoute: () => rootRoute,
```

## 6. 平滑迁移与灰度双轨策略

```
                        Nginx 网关流量切流
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
   [旧版路径 / (按路由黑白名单)]            [新版路径 /next/ (灰度分流)]
            │                                     │
    旧版工程运行中                            新版 Vite 5 工程
            └──────────────────┬──────────────────┘
                               ▼
                   共享 `packages/api-client`
```

1. **双应用并行**：新 Vite 5 工程与旧工程协同构建，前端通过 Nginx 针对指定路由黑白名单做路径灰度分流。
2. **底层 API 共享**：优先完成 `packages/api-client` 的下沉，新旧工程引入同一个 API 客户端。
3. **渐进式组件替换**：按页面复杂度（Dashboard → 基础列表页 → 复杂 DAG 画布）逐步切流。
4. **回滚保障**：通过 `window.__ENABLE_NEW_ARCH__` 特性开关控制新版页面显示，保留旧路由平滑回滚能力。

## 7. 风险防控与预案

| 潜在风险点 | 风险影响度 | 防范与应对策略 |
|-----------|-----------|----------------|
| **后端 API Swagger 不完善** | 中 | 在 `packages/api-client` 中允许手写 Zod Schema 兜底，逐步推动后端补齐规范 |
| **AntD 5 与 Tailwind 样式冲突** | 中 | 关闭 Tailwind 全局 Preflight 样式重置，通过 CSS 作用域修饰符限定样式范围 |
| **DAG 画布复杂度较高** | 高 | 独立成 `packages/dag-next` 包，首期保留 AntV X6 核心，优先进行状态与数据层抽离 |
| **团队构建工具习惯切换** | 低 | 统一提供脚手架命令 `pnpm create:feature`，制定清晰的开发者 Onboarding 文档 |
