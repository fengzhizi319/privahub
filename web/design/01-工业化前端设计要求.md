# 工业化前端软件设计要求规范

> 版本：3.0（最终标准版）| 适用范围：企业级 B 端隐私计算管理平台前端
> 本规范定义了 SecretPad 前端工业化软件建设必须满足的 13 个核心维度标准与评估矩阵。

---

## 一、架构设计（Architecture）

### 1.1 分层架构

优秀的前端必须遵循清晰的分层，采用 Clean Architecture + FSD 融合模型：

| 层级 | 职责 | 约束 |
|------|------|------|
| **Presentation** | 纯 UI 组件、页面布局、交互反馈 | 不包含业务逻辑，仅消费 ViewModel/Props |
| **Application** | 用例编排、状态管理、路由守卫 | 协调 Domain 与 Infrastructure |
| **Domain** | 业务实体、规则、领域事件、端口接口 | 零外部依赖，纯 TypeScript，可独立单测 |
| **Infrastructure** | API 客户端、存储、日志、监控 | 实现 Domain 定义的 Port 接口，不引用上层 |
| **Shared / Core** | 设计系统、通用 hooks、类型、配置 | 零业务语义，可被任何层引用 |

### 1.2 模块化原则

- **Feature-Sliced Design (FSD)**：按业务领域（而非技术类型）组织目录
- **模块自治**：每个 feature 包含自己的 `api/` `model/` `lib/` `ui/` `tests/`
- **单向依赖**：上层可引用下层，禁止反向引用和跨层循环依赖
- **Public API 屏障**：每个模块通过 `index.ts` 暴露唯一入口，内部实现不可直接引用
- **共享层独立**：`shared/` 存放无业务语义的通用工具、UI 原语、配置
- **跨 Feature 通信**：禁止直接引用，通过 Shared 事件总线或 URL 参数协调

### 1.3 Monorepo 管理

- 使用 pnpm workspace + Turborepo 管理多包（远程缓存加速 CI）
- 包粒度：`app`（应用壳）、`features/*`（业务模块）、`packages/*`（design-system / api-client / dag）、`shared/*`（通用库）、`tooling/*`（工程配置）
- 版本策略：内部包 `workspace:*`，外部依赖统一 catalog 管理
- 任务编排：Turborepo pipeline 定义 lint → typecheck → test → build 依赖图

## 二、技术选型标准

### 2.1 核心框架

| 维度 | 要求 | 推荐 |
|------|------|------|
| 框架 | React 18+，支持 Concurrent Mode | React 18（稳定）→ 19 渐进升级 |
| 构建 | Vite 5+，HMR < 200ms，冷启动 < 2s | Vite 5 |
| 语言 | TypeScript 5+ strict mode，禁止 `any` | TS 5.x |
| 路由 | 类型安全路由，支持 loader/searchParams 序列化 | TanStack Router |
| 服务端状态 | 缓存、去重、重试、乐观更新 | TanStack Query v5 |
| 客户端状态 | 轻量、可测试、中间件生态 | Zustand + Immer |
| 表单 | 类型安全校验、高性能 | React Hook Form + Zod |
| 样式 | Design Token + 原子化 + 运行时主题 | Tailwind CSS + CSS Variables |
| API 生成 | 零运行时、端到端类型 | openapi-typescript + openapi-fetch |
| 运行时校验 | 开发环境 schema 验证 | Zod（生产仅上报 Sentry） |

### 2.2 质量工具链

| 工具 | 用途 |
|------|------|
| ESLint 9 (flat config) + typescript-eslint strict | 代码规范 |
| Biome | 格式化（替代 Prettier，速度更快） |
| `tsc --noEmit` | CI 中强制类型检查 |
| Vitest + Testing Library + MSW | 单元/集成测试 |
| Playwright | E2E 测试 |
| rollup-plugin-visualizer | 产物分析，CI 中设置 size budget |
| Husky + lint-staged + commitlint | 提交门禁，Conventional Commits |
| axe-core | CI 中可访问性自动检测 |

### 2.3 CI/CD 流水线

```
Push → Lint + TypeCheck + Unit Test → Build → E2E → Deploy Preview → Production
```

- PR 必须通过所有检查才能合并
- 构建产物带 content hash，支持长期缓存
- 部署支持灰度发布 / 蓝绿部署
- 回滚时间 < 1 分钟
- 视觉回归：Chromatic / Percy 截图对比（可选）

## 三、设计系统（Design System）

### 3.1 Design Token 体系

```
Global Token → Alias Token → Component Token
```

- 颜色、字体、间距、圆角、阴影、动效全部 Token 化
- 支持多主题（亮色/暗色/品牌色/高密度）运行时切换
- Token 以 JSON Schema 管理，通过 Style Dictionary 编译为 CSS Variables / TS 常量
- Ant Design 5 通过 ConfigProvider 消费 Token，保持兼容

### 3.2 组件库规范

- 基于 Ant Design 5 二次封装 + Headless UI 原语扩展
- 每个组件必须包含：Props 类型完备、Storybook Story、单元测试、a11y 测试
- 组件 API 设计遵循最小惊讶原则，支持 `as` / `className` / `style` 透传
- 复合组件使用 Compound Component 模式处理复杂交互

### 3.3 布局系统

- 响应式栅格：支持 1920 / 1440 / 1280 断点
- 固定侧边栏 + 弹性内容区
- 页面骨架屏（Skeleton）作为加载态标准
- 图标统一尺寸网格（16/20/24/32），SVG Sprite 按需加载

## 四、状态管理（State Management）

### 4.1 状态分类

| 类型 | 工具 | 示例 | 原则 |
|------|------|------|------|
| Server State | TanStack Query v5 | API 数据缓存、分页、乐观更新 | 不存入全局 store |
| Client State | Zustand + Immer | 用户信息、主题、权限、UI 状态 | 全局状态最小化 |
| URL State | TanStack Router searchParams | 筛选条件、分页、Tab | 类型安全序列化 |
| Form State | React Hook Form + Zod | 表单校验、提交 | 就近管理 |
| Local UI State | React useState/useReducer | 弹窗开关、展开折叠 | 能在组件内解决不上提 |

### 4.2 核心原则

- 服务端数据由 Query 库管理缓存，不存入全局 store
- 全局状态最小化：仅存放跨页面共享的 UI 状态
- 状态就近原则：能在组件内解决的不上提
- Zustand store 可销毁、可隔离，支持微前端/SSR 场景

## 五、API 层（API Layer）

### 5.1 类型安全

- 从 OpenAPI/Swagger 自动生成 TypeScript 类型和请求函数（openapi-typescript）
- 运行时校验：Zod 对响应做 schema 验证（开发环境报错，生产上报 Sentry）
- 统一错误处理：拦截器 → 错误分类（网络/业务/权限）→ Toast / 全局错误页

### 5.2 请求规范

- 统一 request 实例：baseURL、timeout、retry（指数退避）、cancel
- Token 自动刷新：401 → refresh → 重放请求（无感续期）
- 请求去重：相同 GET 请求合并（TanStack Query 内置）
- 乐观更新：mutation 先更新 UI，失败回滚
- 离线检测 + 自动重试

## 六、性能（Performance）

### 6.1 核心指标

| 指标 | 目标 |
|------|------|
| LCP (Largest Contentful Paint) | < 2.0s |
| INP (Interaction to Next Paint) | < 200ms |
| CLS (Cumulative Layout Shift) | < 0.1 |
| TTI (Time to Interactive) | < 3.0s |
| TTFB | < 800ms |
| Bundle Size (initial) | < 300KB gzip |

### 6.2 优化策略

- **代码分割**：路由级 + 组件级懒加载（React.lazy + Suspense）
- **Tree Shaking**：ESM only，禁止 `import *`，sideEffects 标记
- **缓存策略**：TanStack Query stale-while-revalidate + 持久化缓存
- **虚拟化**：长列表使用 @tanstack/virtual（> 100 行表格/列表）
- **图片**：WebP/AVIF + srcset + loading="lazy"
- **预加载**：关键路由 prefetch（modulepreload），字体 font-display: swap
- **Web Worker**：CPU 密集计算（DAG 布局、大数据解析）移入 Worker
- **产物分析**：集成 visualizer，CI 中设置 size budget 阻断

## 七、安全（Security）

### 7.1 输入安全

- XSS 防护：默认转义，富文本使用 DOMPurify
- CSP：配置 Content-Security-Policy 严格策略
- 禁止 `dangerouslySetInnerHTML`，必须使用时需 code review 审批

### 7.2 认证与授权

- Token 存 httpOnly cookie（后端写入），前端仅维护内存状态
- 路由级权限守卫（`RequiredAuth` + `RequiredPermission`）+ 按钮级权限指令
- API 请求自动携带 CSRF token
- 会话过期自动刷新 + 无感续期
- RBAC 统一模型，平台类型（CENTER/EDGE/P2P）由后端返回

### 7.3 依赖安全

- `pnpm audit` 在 CI 中阻断高危漏洞
- Dependabot / Renovate 自动更新依赖
- 锁定文件 (lockfile) 必须提交，禁止 `latest` 版本

## 八、可访问性（Accessibility）

- 符合 WCAG 2.1 AA 级标准
- 语义化 HTML：正确使用 heading、landmark、`role`、`aria-*`
- 键盘导航：所有交互元素可 Tab 到达，焦点可见
- 屏幕阅读器：动态内容变化使用 `aria-live`
- 颜色对比度 ≥ 4.5:1
- CI 中集成 axe-core 自动化检测

---

## 九、可观测性与错误处理（Observability）

### 9.1 监控体系

- **错误监控**：Sentry 集成，捕获 JS 异常 + Promise rejection + 资源加载失败
- **性能监控**：Web Vitals 上报 + 自定义 Performance Mark
- **行为追踪**：关键操作埋点（页面 PV、按钮点击、接口耗时），支持漏斗分析
- **日志**：结构化日志（level + timestamp + context），生产仅上报 warn+，可动态调整

### 9.2 错误处理策略

- 全局 ErrorBoundary 兜底，避免白屏
- 路由级错误边界，局部降级而非整页崩溃
- API 层统一拦截：网络错误 / 业务错误 / 权限错误 分类处理
- 用户友好提示 + 开发者详细上下文
- 错误 5 分钟内可定位（Sentry source map + trace）

## 十、国际化（i18n）

- 使用 ICU MessageFormat 标准
- 文案抽离至独立 JSON/YAML，禁止硬编码
- 支持 RTL 布局
- 日期/数字/货币使用 `Intl` API
- 翻译工作流：提取 → 翻译平台 → 自动回填

## 十一、测试策略

### 11.1 测试金字塔

```
        /  E2E (Playwright)  \        ← 关键用户流程
       / Integration (RTL+MSW) \      ← 组件交互、模块协作
      / Unit (Vitest)            \    ← 纯函数、hooks、domain
```

### 11.2 覆盖率要求

| 层级 | 最低覆盖率 |
|------|-----------|
| Domain / Utils | 90% |
| Application / Hooks | 80% |
| UI Components | 70% |
| E2E 关键路径 | 100% 覆盖核心流程 |

### 11.3 测试规范

- 测试文件与源码同目录 `*.test.ts(x)`
- 使用 MSW (Mock Service Worker) 模拟 API
- 快照测试仅用于稳定组件，禁止滥用
- CI 中测试失败阻断合并
- 视觉回归：Chromatic / Percy 截图对比（Design System 组件）

## 十二、可扩展性设计

- **微前端就绪**：模块边界清晰，可按需拆分为独立部署单元（Module Federation）
- **插件机制**：支持运行时注册路由、菜单、组件
- **配置驱动**：表单、表格、流程通过 JSON Schema 配置生成
- **API 适配层**：后端接口变更只需修改 Infrastructure 层，不影响 UI
- **SSR 预留**：入口分离（entry-client / entry-ssr），未来可接入

- Storybook：组件文档 + 交互 Playground
- ADR（Architecture Decision Records）：记录重大技术决策
